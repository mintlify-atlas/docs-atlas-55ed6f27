Mundo Escolar is a fully normalized relational database built on SQL Server 2022 for **Librería y Papelería Mundo Escolar** — a school bookstore and stationery shop. It manages every operational layer of the business: who can log in and what they can do, which customers are on file, what products and services are stocked, how goods are purchased from suppliers, and how sales are invoiced and collected. The schema is designed for clarity and extensibility, mapping directly from a formal Entity-Relationship Model (MER) to production-ready T-SQL tables.

## Project Overview

Mundo Escolar is a university case study developed during the **II Semester 2026, Group \#1**. The goal is to implement a complete, production-grade relational database for a real-world school bookstore scenario — from user authentication and role-based access control all the way through billing and payment reconciliation.

The database contains **24 tables** organized across **5 business domains**. Every table is created with explicit primary key constraints, all relationships are enforced through foreign keys, and uniqueness is guaranteed on natural identifiers such as user email addresses, client IDs, and supplier tax numbers.

## Technology Stack

| Component | Detail |
|---|---|
| **Database Engine** | Microsoft SQL Server 2022 |
| **Query Language** | T-SQL (Transact-SQL) |
| **Compatibility** | SQL Server 2022 (v16) |
| **Custom Type** | `BOOL` alias type (created from `BIT`) |
| **Collation** | Server default (Latin1_General recommended for Spanish content) |
| **Authorization** | Database owner set to `sa` to prevent Error 15404 in SSMS diagrams |

### The `BOOL` Alias Type

A custom alias type named `BOOL` is created from the native `BIT` data type early in the setup script:

```sql
CREATE TYPE BOOL FROM BIT
```

This type is used throughout the schema on every `Estado` (status) column and other boolean flags. It exists purely for **MER compatibility** — the logical data model uses `BOOL` as a first-class type, and the alias keeps the physical schema in exact correspondence with the design diagrams without introducing any runtime overhead.

## Database Sizing

The database is provisioned with generous initial allocations and controlled auto-growth to avoid fragmentation under typical bookstore workloads:

| File | Initial Size | Maximum Size | Auto-Growth |
|---|---|---|---|
| **Data file** (`MUNDO_ESCOLAR_data.mdf`) | 3 GB | 20 GB | 1 GB |
| **Log file** (`MUNDO_ESCOLAR_log.ldf`) | 1 GB | 5 GB | 512 MB |

These values are defined at the top of `Estructura.sql` inside the `CREATE DATABASE` statement and can be adjusted before first deployment to match the available disk capacity of the target server.

<Note>
  The `FILENAME` paths in `Estructura.sql` are hardcoded to `C:\SQLData\MUNDO_ESCOLAR_data.mdf` and `C:\SQLLog\MUNDO_ESCOLAR_log.ldf`. These directories **must exist** on the SQL Server host before the script is executed, or the `CREATE DATABASE` statement will fail. If your server uses different drive letters or directory layouts, update both `FILENAME` values accordingly before running the script.
</Note>
