The **MUNDO\_ESCOLAR** database contains 24 tables organized into 5 functional domains: Security, Clients, Inventory, Purchases, and Sales & Billing. The schema was designed following a normalized Entity-Relationship Model (MER) for a school bookstore and stationery shop, ensuring referential integrity across all domains through explicit foreign-key constraints and unique indexes.

## Design Decisions

The MUNDO\_ESCOLAR schema applies a consistent set of conventions across all 24 tables:

- **`BOOL` alias type** — A custom type alias defined as `CREATE TYPE BOOL FROM BIT`. Used for all boolean status flags (e.g., `Estado`) throughout the schema, providing semantic clarity that matches the original MER diagram.
- **`IDENTITY(1,1)` primary keys** — Every table uses a surrogate integer primary key with auto-increment seeded at 1 and incrementing by 1. No natural keys are used as primary keys.
- **`VARCHAR` with explicit lengths** — All character columns declare an explicit maximum length (e.g., `VARCHAR(50)`, `VARCHAR(100)`, `VARCHAR(255)`) to enforce data boundaries at the database engine level.
- **`DECIMAL(12,2)` for monetary values** — Most currency columns (`Precio_Venta`, `Monto_Total`, `Saldo_Pendiente`, `Costo_Unitario`, `Compra_Producto.Subtotal`, etc.) use `DECIMAL(12,2)`, supporting values up to 999,999,999,999.99 with two decimal places of precision. **Exception:** `Venta_Producto.Cantidad` and `Venta_Producto.Subtotal` are both defined as `VARCHAR(50)` in the schema — an anomaly that requires `CAST` or `CONVERT` for any numeric operation. Similarly, `Producto.Stock_Actual` is `VARCHAR(50)` rather than a numeric type. See the [Inventory](./inventory) and [Sales](./sales) pages for query guidance.
- **`DATETIME` for timestamps** — All date/time columns use the `DATETIME` type, including `Fecha_Registro`, `Fecha_Compra`, `Fecha_Emision`, `Fecha_Vencimiento`, and `Fecha_Hora` in the audit log.

## Constraints

The following unique constraints are defined in the schema to enforce business-rule uniqueness beyond the primary key:

| Constraint Name | Table | Column | Purpose |
|---|---|---|---|
| `UQ_Rol_Nombre` | `Rol` | `Nombre` | No two roles may share the same name |
| `UQ_Permiso_Nombre` | `Permiso` | `Nombre` | No two permissions may share the same name |
| `UQ_Usuario_Correo` | `Usuario` | `Correo` | Each user must have a unique email address |
| `UQ_Cliente_Identificacion` | `Cliente` | `Identificacion` | Each customer identification (national ID / tax number) must be unique |
| `UQ_Proveedor_Cedula_Juridica` | `Proveedor` | `Cedula_Juridica` | Each supplier must have a unique legal ID number |
